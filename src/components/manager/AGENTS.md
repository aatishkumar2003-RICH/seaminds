# Manager component rules

- Company Crew intake: approved managers create office records via RPC `company_crew_import` into `company_crew_records` (shared ID sequence `next_crew_unique_id`, docs in private `company-crew-docs/{uid}/{record}/`); crew accept at `/claim/:token` via `accept_crew_claim` (new accounts take the reserved ID, existing crew keep theirs, company entries appended with `source:'company'`, fleet link set active). Why: managers onboard rosters fast while each seafarer still gives explicit consent.
- Interview Studio results use paged RPC `campaign_candidates_v2` (search/filter/sort, max 100 per page) and click-through `manager_candidate_dossier` (campaign owner only; CV/contacts only for admin-approved managers; wellness flags excluded). Custom training briefings come from `training-module-draft` (manager-only, nothing stored, sent inside the invite text). Why: thousands of candidates without scrolling, consent-safe.
- Manager training radar: crew share progress by opening an invite link with `mt=<manager_profiles.id>` (RPC `crew_share_training` → `manager_training_links`); managers read only via `manager_training_radar`/`manager_training_detail` (20s polling, interview scores only when crew shared). Why: consent-gated live tracking without exposing private tables.
- Training invites: sending (any channel) calls RPC `manager_link_training_crew` (approved managers) — links existing crew by email/phone to `manager_training_links`, else stores email in `manager_training_invites`; trigger links on crew sign-up. Why: radar fills without waiting for the crew to open the link.
- Training email invites: sent via `send-training-invite` (manager-only, Resend, 150/day per manager, 10-min duplicate skip); never `window.open(mailto:)`. Why: mailto popups left a blank tab and depended on a desktop mail app.
- Manager invite views group by person: interviews via RPC `manager_interview_people` (all campaigns, one card per crew/email/phone with invite history), training sends logged by `manager_log_training_send` into owner-read `manager_training_sends` and listed via `manager_training_sent`; `_manager_crew_base` includes these invitees so Fleet Overview shows them, and radar/roster/sent lists all accept a rank filter. Why: repeat sends must not multiply rows and nothing a manager sends may go missing.
- Manager crew pickers for training use RPC `manager_training_pool` (company records + radar links + interview invitees + training sends, deduped by crew/email/phone); the Interview & Training tabs share one per-person activity board merging `manager_interview_people` and `manager_training_sent`. Why: managers must find anyone they have contacted in one place.
- Add Crew CV intake (single auto-fill and bulk up to 20) goes through `src/lib/cvToCrewRow.ts` → `parse-cv-documents` → `company_crew_import`, original CV archived in `company-crew-docs`. Why: one CV reader for every format.
- Interview invites: choosing a rank lists matching crew from the manager's own pool (`manager_training_pool`) via `RankCrewPicker`; bulk emails go through `send-interview-invite` in batches of 5. Why: no retyping, reuses the 24h duplicate guard.
- Manager training sends call RPC `manager_assign_training` (links crew + writes `crew_training_assignments` source 'manager'; unregistered emails keep pending slugs applied at sign-up). Interview focus chips follow the rank's department. Why: whatever a manager requests must appear in the crew's Required tab.
- Invite target dates: interview_campaigns.target_date and manager_training_sends.target_date (via `manager_log_training_send` p_target) are soft complete-by dates shown in invites and as due badges (`src/lib/targetDate.ts`); never use `closes_at` for them. Radar filters by rank/vessel (from company_crew_records)/practice date server-side. Why: late crew must be flagged, not locked out.
- Cadet Academy is separate from crew interviews: `cadet_enrollments`/`cadet_week_results` written only via RPCs (`manager_enroll_cadet`, `cadet_submit_week` server-grades with `_cadet_key`), course text in `src/lib/cadetCurriculum.ts` (no answer keys), UI = manager `?tab=cadets` and crew `/training?tab=cadet`; Record Book PDF built from `manager_cadet_dossier`. Bulk lists parse via pure `src/lib/cadetBulk.ts`; invites email through existing `send-training-invite` (no new email function). Why: cadet cohort monitored apart from officers, no forgeable scores.
