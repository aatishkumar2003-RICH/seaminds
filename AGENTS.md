# Architecture rules

- Subdirectories (e.g. `supabase/functions/`) have their own `AGENTS.md`; read it before changing files there.
- Heartbeat `save_checkpoint` never clears an interruption; only `confirm_resume` (same paper + persisted answer) does. Why: a reconnect is not proof of recovery.
- Final scoring is single-flight via `final_scoring_lease` on `scoring_jobs`; a validated AI result is cached before commit and reused. Why: polling and concurrent requests must not trigger repeated AI calls.
- Pre-paper start failures are recorded in `assessment_start_incidents` (owner-bound, server-classified); no fake checkpoint or paper. Why: failures before issuance must be visible and recoverable without bypassing readiness.
- Readiness uses exact rank/context `blueprint_coverage*`, not global counts. Why: rows alone do not prove readiness.
- Assessment `scoring_tier` (QUICK_PROFILE / CV_VERIFIED) and `assessment_round` are set server-side by trigger `trg_set_assessment_scoring_tier` at creation; clients never choose them. Why: a score's evidence basis must not be forgeable.
- DORA help knowledge lives in `dora_articles` (Postgres FTS via `dora_search_articles`, max 4 published hits); own-user context only via `dora_get_my_context()` keyed by auth.uid(); metrics/gaps store no raw conversation text. Why: grounded retrieval, no cross-user leakage.
- Every Apply button routes through `src/lib/applicationRouter.ts` (WhatsApp → recruiter email → official site → flyer); SeaMinds-published adverts keep the agency in `job_postings.recruiter_name` and `notify-application` never falls back to the publishing account's email. Why: applications must reach the actual recruiter, and toasts claim only what happened.
- Service-worker runtime caching rules live in `src/lib/pwaCacheRules.ts`: only listed public tables may be cached; every other backend call is NetworkOnly. Why: cached personal responses showed stale application state.
- Feeds use keyset cursors per source (`loadVacancyPage`); no vacancy is hidden by age (old external = "hiring not confirmed"). Inventory pages and lifecycle actions go via `src/lib/vacancyLifecycle.ts`. Why: no false removals; one secure delete path.
- Build metadata comes from vite.config.ts (/version.json NetworkOnly, not precached); UI reads src/lib/releaseInfo.ts. Why: identifiable builds, no stale update checks.
- Assessments are created/resumed only via `open_assessment_v2(mode, invite_id, restart)` (client wrapper `src/lib/assessmentGateway.ts`); mode is explicit (PROFILE / CV_BASED), context is server-derived, one in_progress row per (crew, mode, context), evidence snapshot frozen at creation, preflight confirmation never automatic. Why: no client-forged tiers, no duplicates, old certificates stay truthful.
- Manager pages share `ShipManagerLayout`; pages keep auth/logic, tabs use URL queries. Why: one shell
- Interview profile preparation stays on the token page with embedded QuickProfile/CvUpload; only confirmed saves advance, never client-selected scoring tiers. Why: truthful evidence.
- Vacancy ownership lives in `job_postings.recruiter_name` (own company vs distinct agency; NULL = legacy); routing uses raw `recruiterName` (`isThirdPartyAdvert`). Publishing is one atomic INSERT per batch; uncertain batches reconcile by `posting_batch_id`. Why: no routing-mode field; a timeout is not proof of no commit.
- Vacancies never auto-expire: feeds filter `status = 'active'`; `expires_at` = `NO_EXPIRY_COMPAT`. Delete is blocked when applications exist. Why: retention is an owner decision.
- Vacancy country detection (phone → agency keyword → email ccTLD) in `src/lib/vacancyOrigin.ts` must mirror SQL `vacancy_origin_of()`. Why: both sides must agree.
- Training selection/dwell/grading use `training_*` RPCs, targeting either an interview invite or a job application (ownership checked in `training_resolve_crew`); quiz keys stay admin-only; `issue_paper` caps retention near 25%. Roster counts use owner-scoped `campaign_training_summary`, refreshed on resume. Why: truthful completion, privacy, blueprint coverage.
- Credits live in `credit_ledger` (user id in `manager_user_id`, for crew too); welcome/referral/milestone awards are server-only and unique per user/reason. `credit_program_settings` drives rewards/reminders; owner-only `credit_plans` are global private drafts with audit history; wallet reconciles persisted milestones. Why: no farming or forged grants.
- Ship marketplace is connection-only: `ship_listings` posts only by `is_marketplace_seller` (approved manager + admin-granted `marketplace_sellers` row, requested by email); featured/hidden admin-only (trigger); photos private bucket + signed URLs. Why: no brokerage liability.
- Crew menu = `NAV_ITEMS` sections rendered by `GroupedNav`. Why: one menu.
- Company compliance: `company_compliance` + RPCs, files in private `company-documents/{uid}/`; each request/submission/approval emails via `company-compliance-notify`. Why: one review place, one action = one email.
- Excel CVs: browser unzip in `src/lib/xlsxCv.ts`, text to `parse-cv-documents`; CV declaration versioned in `crew_cv_data.medical.declaration`. Why: no schema change.
- Maritime English progress is server-recorded via `record_english_attempt` (one daily per UTC day, +5 credits per 7-day streak, unique ledger reason); scores are self-practice, shown to managers only as recent average. Why: device-independent streaks without farmable credits.
- Crew↔company joining issues use `lineup_tickets` via `raise_lineup_ticket`/`reply_lineup_ticket`/`set_lineup_ticket_status`; party = `lineup_party_role()` (crew, owning manager, admin). Raiser waits 48h before escalating; repatriation escalates immediately. Why: fair, private two-sided mediation per joining.
- Crew Management Tools (/manager/crew-desk) reads crew data only via `crew_desk_roster`/`crew_desk_master_record` (approved owning manager; full record only after crew confirms joining; each open logged in cv_access_log). Why: one master record, consent-gated.
- Principal CV templates use owner-private `principal_cv_templates` and `principal-templates` storage; reviewed paragraph/cell mappings populate the original DOCX/XLSX locally, with explicit photo-slot replacement and crew-declaration gating. Why: preserve authorized company forms without repeated AI cost, guessed data or cross-manager access.
- SEA contracts live in `sea_contracts` (owning approved manager via `_crew_desk_app_owned`; crew sees issued/signed/completed only); trigger `sea_contract_guard` sets owner/crew, requires crew-confirmed joining, enforces draft→issued→signed→completed/cancelled and locks wage/period after signing. Calculations/PDF in `src/lib/seaContract.ts`. Why: tamper-proof contract terms feeding the future portage bill.
- Fleet Overview derives state from roster + sea_contracts (completed = signed off); reliever = sea_contracts.reliever_application_id (owner-checked trigger); safe manning per vessel in owner-only vessel_manning; payroll is grouped per currency, never summed across. Why: one source of truth, no mixed-currency totals.
- Crew Desk operating model (crewing_agency / ship_manager) lives in owner-only `crew_workspace_settings`, asked on first entry; safe-manning and senior-rank warnings apply to all vessels for ship_manager, and only to vessels with a `vessel_manning` row for agencies. Why: agencies supplying single positions must not see false manning alarms.
