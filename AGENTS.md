# Architecture rules

- Read subdirectory `AGENTS.md` before edits, including `src/` and `supabase/functions/`.
- Heartbeat `save_checkpoint` never clears an interruption; only `confirm_resume` (same paper + persisted answer) does. Why: a reconnect is not proof of recovery.
- Final scoring is single-flight via `final_scoring_lease` on `scoring_jobs`; a validated AI result is cached before commit and reused. Why: polling and concurrent requests must not trigger repeated AI calls.
- Pre-paper start failures are recorded in `assessment_start_incidents` (owner-bound, server-classified); no fake checkpoint or paper. Why: failures before issuance must be visible and recoverable without bypassing readiness.
- Readiness uses rank/context `blueprint_coverage*`, not global counts; rows alone prove nothing.
- Assessment `scoring_tier` (QUICK_PROFILE / CV_VERIFIED) and `assessment_round` are set server-side by trigger `trg_set_assessment_scoring_tier` at creation; clients never choose them. Why: a score's evidence basis must not be forgeable.
- DORA help knowledge lives in `dora_articles` (Postgres FTS via `dora_search_articles`, max 4 published hits); own-user context only via `dora_get_my_context()` keyed by auth.uid(); metrics/gaps store no raw conversation text. Why: grounded retrieval, no cross-user leakage.
- Every Apply button routes through `src/lib/applicationRouter.ts` (WhatsApp → recruiter email → flyer); SeaMinds-published adverts keep the agency in `job_postings.recruiter_name` and `notify-application` never falls back to the publishing account's email. Why: applications must reach the actual recruiter, and toasts claim only what happened.
- Feeds use keyset cursors per source (`loadVacancyPage`); no vacancy is hidden by age (old external = "hiring not confirmed"). Inventory pages and lifecycle actions go via `src/lib/vacancyLifecycle.ts`. Why: no false removals; one secure delete path.
- Build metadata comes from vite.config.ts (/version.json NetworkOnly, not precached); UI reads src/lib/releaseInfo.ts. Why: identifiable builds, no stale update checks.
- Assessments are created/resumed only via `open_assessment_v2(mode, invite_id, restart)` (client wrapper `src/lib/assessmentGateway.ts`); mode is explicit (PROFILE / CV_BASED), context is server-derived, one in_progress row per (crew, mode, context), evidence snapshot frozen at creation, preflight confirmation never automatic. Why: no client-forged tiers, no duplicates, old certificates stay truthful.
- Manager pages share `ShipManagerLayout`; tabs use URL queries. Why: one shell.
- Business help uses floating DORA and support-submit; only submitted reports reach admins with ticket-keyed alerts. Why: private, consistent help.
- Interview profile preparation stays on the token page with embedded QuickProfile/CvUpload; only confirmed saves advance, never client-selected scoring tiers. Why: truthful evidence.
- Vacancy ownership lives in `job_postings.recruiter_name` (own company vs distinct agency; NULL = legacy); routing uses raw `recruiterName` (`isThirdPartyAdvert`). Publishing is one atomic INSERT per batch; uncertain batches reconcile by `posting_batch_id`. Why: no routing-mode field; a timeout is not proof of no commit.
- Vacancies never auto-expire: feeds filter `status = 'active'`; `expires_at` = `NO_EXPIRY_COMPAT`. Delete is blocked when applications exist. Why: retention is an owner decision.
- Vacancy country detection (phone → agency keyword → email ccTLD) in `src/lib/vacancyOrigin.ts` must mirror SQL `vacancy_origin_of()`. Why: both sides must agree.
- Training selection/dwell/grading use `training_*` RPCs, targeting either an interview invite or a job application (ownership checked in `training_resolve_crew`); quiz keys stay admin-only; `issue_paper` caps retention near 25%. Roster counts use owner-scoped `campaign_training_summary`, refreshed on resume. Why: truthful completion, privacy, blueprint coverage.
- Credits: server-only unique rewards in `credit_ledger`; owner-only audited `credit_plans`, reward and monetization settings. `get_credit_pricing` exposes effective costs; spending RPCs share the `credits:` user lock. Free mode preserves balances; checkout waits for verified integration. Why: no forged grants or double spending.
- Ship marketplace is connection-only: `ship_listings` posts only by `is_marketplace_seller` (approved manager + admin-granted `marketplace_sellers` row, requested by email); featured/hidden admin-only (trigger); photos private bucket + signed URLs. Why: no brokerage liability.
- Company verification: `company_compliance`, private `company-documents/{uid}/`; `submit_company_verification` → `verify-company` (AI + rule checks, 3/day) auto-verifies clean passes, else flags + emails admin. Why: scale without manual review.
- Maritime English progress is server-recorded via `record_english_attempt` (one daily per UTC day, +5 credits per 7-day streak, unique ledger reason); scores are self-practice, shown to managers only as recent average. Why: no farmable credits.
- Crew↔company joining issues use `lineup_tickets` via `raise_lineup_ticket`/`reply_lineup_ticket`/`set_lineup_ticket_status`; party = `lineup_party_role()` (crew, owning manager, admin). Raiser waits 48h before escalating; repatriation escalates immediately. Why: fair, private two-sided mediation per joining.
- Crew Management Tools (/manager/crew-desk) reads crew data only via `crew_desk_roster`/`crew_desk_master_record` (approved owning manager; full record only after crew confirms joining; each open logged in cv_access_log). Why: one master record, consent-gated.
- SEA contracts live in `sea_contracts` (owning approved manager via `_crew_desk_app_owned`; crew sees issued/signed/completed only); trigger `sea_contract_guard` sets owner/crew, requires crew-confirmed joining, enforces draft→issued→signed→completed/cancelled and locks wage/period after signing. Why: tamper-proof terms for the portage bill.
- Fleet Overview derives from roster + sea_contracts; safe manning in owner-only vessel_manning. Why: one source of truth.
- Operating model (crewing_agency/ship_manager) in owner-only `crew_workspace_settings`; manning warnings fleet-wide for ship_manager, only `vessel_manning` vessels for agencies. Why: no false alarms for agencies.
- Portage bill rows live in `portage_entries` (one per contract per month, owner = contract manager); trigger `portage_entry_guard` requires a signed/completed contract, copies its currency, enforces draft→finalized→paid and locks paid months. Why: wages derive only from signed SEA terms and settled months cannot be altered.
- Crew appraisals live in `crew_appraisals` (one per signed contract, owner = contract manager); trigger `crew_appraisal_guard` computes overall, requires appraiser + training for rehire_with_training, and locks after finalizing. Why: re-employment verdicts must be tamper-proof.
- Cert radar only via `crew_desk_certificate_radar` (crew-confirmed joinings); crew read own finalized/paid `portage_entries` via RLS. Why: consent gating, MLC A2.2.
- Offer acceptance = outcome 'accepted' (Processing, no lock); only trigger `place_on_sea_signed` places crew on SEA signing. `submit_application` reopens closed applications, never re-alerts open ones. Why: crew free until signed; no recruiter spam.
- Crew next steps via `get_my_action_hub()`; interview timing only via `manager_schedule_interview`/`respond_interview_schedule`. Why: both parties agree times; no direct client writes.
- Crew pipeline transparency: managers see only aggregate in-talks counts (from `manager-search`), never competitor names; crew step back via RPC `crew_disengage` (outcome 'withdrawn') and `set_inquiries_paused`; trigger auto-withdraws other active applications on placement. Why: no wasted manager effort, crew control, privacy.
- Crew child tables self-heal missing `crew_profiles` via trigger `aa_ensure_crew_profile` (auth.uid() only). Why: no FK save errors.
- /rss.xml and /sitemap.xml regenerate each build (vite.config.ts + scripts/seoFeeds.ts); jobs sitemap = `sitemap` function in robots.txt. Why: static feeds go stale.
- Manager crew roster is unified via RPC `manager_unified_crew` (server-paged, merges company crew, training links and confirmed joinings; CV-data certs/sea service override office copies) and `manager_unified_crew_detail` (logs cv_access_log; crew-owned CV/contacts only for admin-approved managers). UI: `UnifiedCrewBoard` on dashboard fleet tab and Crew Desk Fleet Overview. Why: one live crew source that scales to 10,000 crew.
- LOCKED candidate names: manager boards never show a raw email as a name when any name exists. Order: crew profile → manager's company crew record → invite name → name before " - " in the interview title (`name_from_campaign_title`; trigger `trg_invite_default_name` fills blank invite names). Improve in place; never remove a tier. Why: Esther's board regressed to emails repeatedly.
