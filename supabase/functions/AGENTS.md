# Edge function rules

- Pure AI/email provider adapters live in `supabase/functions/_shared/finalAi.ts` with no imports so vitest can test them. Why: deterministic mocked-fetch tests without a new test runtime.
- DORA answers go through `dora-assist`: deterministic exam-integrity block and no-article fallback before any AI call; AI sees only retrieved published articles + `dora_get_my_context`. Why: no invented procedures, no exam leakage, minimal AI cost.
- Recruiter outreach only via `recruiter-outreach` (twice-daily cron, per-run cap; contacts from `recruiter_outreach_sync()` merging job_postings, external_vacancies and company_contacts; engaging/nurture recruiters also get the Friday `weekly-briefing` with the outreach opt-out link); stops on replied/joined/unsubscribed/bounced. Why: sender reputation and opt-out respect.
- Assessment recovery emails go through `recovery_outbox` (leased, attempt-fenced, stable idempotency key); never send from `recovery_claim_due`. Why: crashes must not strand work or mint new links.
- Crew recruiter-email delivery status is read via `notify-application` `kind: "delivery_status"` (own applications, ids only), cached in `vacancyFeed` and refreshed on app resume. Why: an application row alone does not prove the email was accepted.
- Weekly blog briefing only via `weekly-briefing` (cron Tue–Fri, one region/audience per day, per-run cap, stands down near the shared free email ceiling; 90-day no-repeat via `briefing_log`, opt-out in `briefing_optout`). Content is training-only: one lesson (job-digest posts excluded), the free training hub, then a live-count jobs footer. Why: protect the email quota; the briefing sells training, not job dumps.
- WhatsApp marketing leads live only in admin-only `whatsapp_crew_leads`; sends go through `whatsapp-leads` (approved templates only, one per call, client-paced, opt-out never resent). Why: protect number quality and contact lists.
- Daily news blog = `blog-writer` mode `news_briefing` (cron 04:00 UTC): trusted maritime RSS → AI editor pick → SEO briefing with one matched SeaMinds CTA; source links logged in `app_events` to avoid repeats; facts only from the feed summary. Job-count "market_report" posts are no longer scheduled. Why: the blog must read as maritime journalism, not job dumps.
- Maritime Brain knowledge cores (deck/engine topics, safety gates, rank resolution, prompt builder) live in `_shared/maritimeBrain.ts` with no imports; AI functions build prompts from it. Why: one versioned, testable source of maritime knowledge.
- Adaptive interviews go through `maritime-examiner` (stateless turns, auth + rate limit + kill switch + metering; logic in pure `_shared/maritimeExaminer.ts`, deterministic safety flag overrides AI). Length, pillar routing and exit gates are decided by pure `examDecision`/`nextPillar`, never by the AI; pickup questions are plain A–D text lines (no schema). Why: cheap, testable, and the AI cannot clear an unsafe answer or end an interview early.
- New `four_in_one_v1` interviews always complete 14 server-owned turns and store `module_scores`; legacy `adaptive_v1` sessions retain their old gates. English answer mode is stored per turn, and composure prompts prohibit wellness/medical inference. Why: complete four-part evidence while preserving resumes, honest speech claims and sealed privacy.
- Vessel mailbox outreach lives in admin-only `vessel_outreach_contacts` (new batches appended with ON CONFLICT email skip); `vessel-briefing` runs daily (05:00 UTC, after the news desk) sending each active ship one plain-text bulletin built from that day's English news post by pure `_shared/shipBulletin.ts` (no HTML/images/attachments, Resend batch of 50, ≥20h gap per ship, skips when no fresh post); stops on unsubscribed/bounced. Why: satellite mail strips attachments and heavy HTML.
- Admin reporting: `supervisor-agent` sends ONE compiled daily report to the admin inbox at 14:00 UTC (9 PM Jakarta), guarded once per Jakarta day via app_events `supervisor_daily_report`; the 30-min monitor email is paused. Instant sign-in alerts (admin, manager, marketplace seller every sign-in; crew first sign-in/registration) go only through `notify-signup`. Why: owner wants one report plus only critical instant alerts.
- Bounces/complaints arrive only via `resend-webhook` (Svix-verified with RESEND_WEBHOOK_SECRET) which sets outreach contacts to bounced/unsubscribed and logs `email_bounced`; unsubscribe POSTs carry `r=<reason>` logged as `email_unsubscribed` for the daily report. Why: an HTTP 200 from the provider is not proof of delivery.
- Interview follow-ups: campaign `prep_tracks`; trigger `trg_interview_prescribe` assigns top-2 gap modules on completion (score <3.50 or tracks); `interview-followups` (hourly cron) emails daily reminders until done (60-day stop) and improvement plans (max 3, 48h apart) from `interview_followups_due`; email text in pure `_shared/interviewFollowup.ts`. Why: casual self-paced interviews, server-decided follow-up, no WhatsApp cost. Manager-assigned training and cadet weeks get one daily pending digest per crew via `assignment_reminders_due` and one thank-you when all are done (state in `assignment_reminder_state`).
- LOCKED baseline: the `four_in_one_v1` interview, proctor strike rules and CV `sea_service` schema are frozen; improve them in place (prompt/brain/helpers), never rebuild or add parallel interview/CV flows. CV grounding = pure `seaServiceContext` (IMO optional; valid 7-digit IMO → exact ship, else name/type, else rank/vessel), added only to technical turns. Why: repeated rebuilds wasted owner credits.
- Superintendent question seeds live in `_shared/maritimeExemplars.ts` (generated from the owner staging bank, by rank); the examiner adds a few varied seeds to opening technical turns as inspiration only, never a fixed script. Why: rank-real depth while the Brain stays generative and unrestricted.
